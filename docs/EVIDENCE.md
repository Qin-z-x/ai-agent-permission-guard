## Scope and honesty statement

`agent-perm-guard` is a defensive manifest auditor. It does not disclose a new vulnerability, does not claim a new CVE and does not make an agent safe: it reads declared permissions and flags risky combinations. The sample manifests are synthetic. Manifests can be incomplete or dishonest, so the audit must be paired with runtime sandboxing, egress control and least-privilege credentials.

## Limitations

- The audit uses declared permissions; a tool can do more than its manifest says, and a manifest can
  omit fields the auditor would flag. Treat a clean result as a review prompt, not a guarantee.
- Schema tolerance: the loader understands common `tools`/`functions` shapes, but every framework has
  its own dialect; unsupported fields are ignored rather than rejected (documented).
- The YAML parser is a deliberate subset (mappings, sequences, scalars, comments, inline lists);
  anchors, multi-document streams and block scalars are not supported.
- Risk weights are a triage heuristic, not a measurement of real exploitability.
- The real controls are runtime: container/seccomp sandbox, filesystem mounts, network egress policy,
  scoped credentials per tool and human approval for destructive actions.
